# VRC-Draw 线稿与真实绘制路径质量改进方案

## 1. 状态与结论

状态：**阶段一、阶段二和阶段三均已完成；用户实绘确认效果可用，0.2.0默认启用阶段三路径并保留阶段二兼容回退开关**（2026-07-27）。

本文档同时解决两类质量问题：

1. 线稿边缘呈像素锯齿，部分距离很近的线被错误粘连。
2. 绘画路线存在突出短枝、星状毛刺、错误交叉、方框轮廓和整数执行锯齿。

此前方案只在现有路径之后增加直线和三次贝塞尔拟合，只能改善连续折线的锯齿，不能删除已经形成的错误图边。新方案把处理顺序改为：先获得平滑且不粘连的规范线稿，再修正路径拓扑，最后进行矢量拟合和鼠标执行采样。

Photoshop 只作为线稿效果和处理思路的离线参考。软件运行时不依赖 Photoshop、OpenCV、Qt、Eigen 或新的第三方库，所有算法继续使用 C++23 自行实现，也不向普通用户增加阈值、模糊半径等设置。

本方案实施前后都不得修改原图文件。所有调试图和测试结果只写入软件目录或仓库的 `build` 目录。

### 1.1 阶段一实施结果

本轮只实施规范线稿链路，没有开始路径区域分类、毛刺拓扑修复、贝塞尔拟合或鼠标执行采样改造：

- `LineArtDocument` 已分离为灰度覆盖线稿 `coverageLineArt`、二值拓扑线稿 `cleanLineArt` 和现有绘画路线 `strokes`。主界面线稿页与 PNG 导出共同使用灰度覆盖图，路径分析继续使用同源二值拓扑图。
- 已实现 `0.7×`、`1.4×`、`2.8× processingScale` 三尺度的 PS 式颜色减淡响应、受控暗线脊/RGB边界融合和自动响应色阶。原生黑白线稿仍以原始灰度为主，避免为了彩色插画改变已有正确线宽。
- 已取消全图无条件闭运算。程序只删除低响应的单像素错误桥，并仅在端点切线相向、距离受限且走廊存在弱响应支持时补线；近邻平行线合成测试保持分离。
- 灰度覆盖图保留中间覆盖值，拓扑线条核心最低覆盖提高到82%，因此主体保持接近黑色，中间灰度集中在抗锯齿边缘。
- SVG 已改为从灰度覆盖图运行 Marching Squares，插值得到亚像素闭合轮廓，并在 `0.35` 像素误差约束下简化；使用单一 `<path fill-rule="evenodd">` 保留孔洞，不再输出逐像素矩形。

全部14张 `sample` 图片已生成并人工检查灰度线稿；自动测试全部通过，路线越出拓扑墨迹比例为0，所有拓扑组件均被现有路线覆盖。合成测试覆盖近邻平行线、X/T/Y/V交叉、填充圆、填充眼睛和粗细过渡。代表性 SVG 已使用 Chrome 实际渲染，闭环、孔洞和填充结果正常。

MinGW Release 实测数据如下；详细结果位于已被 Git 忽略的 `build/lineart-stage1-final-verified`，可随 `build` 目录删除：

- 14张图片处理耗时：中位数362.5 ms，P95为635 ms。
- PNG与SVG联合导出耗时：中位数101.5 ms，P95为213 ms。
- 最大SVG文件为553.6 KB。
- 包含全样本处理和导出的测试进程峰值工作集为95.5 MB，低于160 MB目标。

本小节记录阶段一结项时的状态；阶段二实施结果见第1.3节。阶段三仍未实施，因此当前仍不宣称已经消除整数执行路线的栅格锯齿。

### 1.2 阶段一后的方案复核结论（历史记录）

结论：**阶段二和阶段三都需要修改，不能直接在现有路径代码上继续叠加规则，因此本次复核不执行阶段二代码。**

复核发现以下实际差异：

1. 阶段一公开结果只有 `coverageLineArt` 和 `cleanLineArt`。三尺度响应在 `BuildPsLineResponse` 内取最大值后被释放，没有保留每个尺度是否支持该像素，也没有保留主切线和来源类型。
2. `coverageLineArt` 不能反过来充当阶段二置信度。它经过自动色阶，而且拓扑核心被强制提升到至少82%覆盖率，适合显示但会抹平“强原生线、弱补线、颜色边界”之间的证据差异。
3. 当前 `BuildRouteSkeleton` 使用全图骨架半径中位数计算一个 `filledRadius`，再把所有粗区统一改成轮廓。这个全局阈值不能可靠区分细长粗笔触和紧凑填充块。
4. 当前 `stableSupport` 只是把二值拓扑缩小到半分辨率后再次骨架化，并不等价于PS三尺度响应稳定性；细而真实的睫毛或发丝可能在缩小过程中消失。
5. 当前 `TraceSkeleton` 会按距离合并交叉簇、删除簇内连接边，再把所有分支最小二乘拟合到同一个公共点。即使最终线段仍位于墨迹内，也可能得到反向延长、星状短枝或错误穿越关系，正好与阶段二目标冲突。
6. 当前无损优化器以“逻辑线段和最终执行线段完全相同”为门禁。阶段三会有意把已验证折线改成直线或贝塞尔，不能继续用这项门禁比较拟合前后；无损优化必须放在拟合之前，拟合需要独立的几何与拓扑门禁。

因此，修订后的阶段二会先让规范线稿提取额外返回**仅在本次处理期间存在的证据图**，然后整体替换现有粗区判断、半分辨率稳定性判断和公共交点拟合。阶段三则以阶段二输出的已验证路线图为唯一输入，并重新定义与无损优化器、`sourceEdgeEnds` 和 `ExecutionPlan` 的衔接。

### 1.3 阶段二实施结果

阶段二已经完成，阶段一线稿结果保持不变，且没有开始直线／贝塞尔拟合或鼠标采样改造：

- `CanonicalLineArtExtraction` 在单次图片处理期间额外保存四字节 `LinePixelEvidence`，包括结构置信度、16档切线、三尺度支持位图以及原暗线、RGB边界、方向补线等来源标记；证据在路线构建后释放，不写入 `ProcessedImage`、设置或导出文件。
- `BuildRouteSkeleton` 改为只计算一次墨迹内距离场，并按局部粗核心、受限扩展、协方差长宽比、骨架长度和端口数区分普通细线、细长粗笔触、紧凑填充块与交叉区。全图 `filledRadius`、半分辨率 `stableSupport` 和统一粗区轮廓化已删除。
- 两端口且方向连续的局部粗片段会保持单中心线，避免长粗发丝被切成小片段后误画成多个矩形；紧凑填充圆、椭圆和黑色图案仍只保留外轮廓及真实孔洞，不生成内部中轴树。
- 图边会汇总低置信度比例、端点置信度、多尺度支持、原生响应、补线比例和区域类型。短终端分支只有同时满足长度、相邻主枝、反向角平分线和弱证据条件才会删除，强证据短睫毛测试保持完整。
- 交叉处理已经替换距离式簇合并和最小二乘公共点。程序从实际骨架边界建立端口，以向外切线进行最小弯曲配对；候选交点必须位于两条正向射线、交叉墨迹和允许距离内，否则使用完全位于交叉区的骨架测地线。
- 浅角X形在骨架化后可能形成两个三端口核心；程序只在同一局部 `Junction` 证据区内合并它们，不按图片尺度或欧氏距离合并，因此两个相近但独立的交叉仍保持分离。三端口保留T/Y终止关系，四端口形成两条穿越路径，五端口以上拆成局部配对和终止关系，不再拉向同一个中心。
- 阶段二折线先经过上述拓扑门禁，再交给现有无损图边分解。`sourceEdgeEnds` 继续保存阶段二图边结束位置；逻辑线段多重集、最终执行覆盖、组件和闭环的零差异门禁仍然有效。它目前只是点索引，不携带区域类型、交叉端口身份或受保护角点，这一限制必须在阶段三准备步骤中解决。

新增合成测试覆盖相近独立交叉、锐角X、反向射线、细长黑矩形、紧凑填充块与细线相接、粗笔触与强证据短睫毛相接以及五端口密集交叉。反向射线测试会明确记录候选被拒绝并改用受墨迹支持的测地线；细长矩形只生成一条中轴，五个有效端口全部保留。

14张样本的阶段二自动与人工验收结果如下：

- `lineart-coverage.bmp` 和 `lineart-topology.bmp` 与 `build/lineart-stage1-final-verified` 逐文件SHA-256一致，差异数为0。
- 路线越出规范墨迹比例全部为0，所有线稿组件覆盖率均为100%。
- 阶段一在眼睛、衣领和头发交叉处可见的星状公共交点、反向突出尾巴已经消失；人工检查发现并修复了 `sample (3)` 长粗发丝上的局部方框路线，未通过放宽组件或越界指标掩盖问题。
- 无损优化前后总笔画数为30,808→13,589，预计总绘制时间为315.61→149.61分钟；全部逻辑线段和最终落笔覆盖保持一致。
- Release正常处理耗时中位数为499.5 ms，P95为777 ms；完整测试进程峰值工作集为128.5 MB，低于160 MB目标。

完整诊断结果保存在被Git忽略的 `build/lineart-stage2-final-verified`，可随 `build` 目录删除。每张样本包含PS响应、置信度、切线、尺度与来源图、区域分类、交叉区、被删毛刺、阶段一／阶段二路线、路线叠加和指标文件。以下是阶段二结项时的历史状态：阶段三当时尚未执行，所以该阶段路线仍是受验证的像素折线，不能把阶段二结果描述为已经完成贝塞尔平滑或最终鼠标锯齿修复。

### 1.4 阶段三实施前复核结论

结论：**阶段三方案需要修改，本次复核不执行阶段三代码。** 直接按原第9～11节实现会丢失阶段二已经确认的结构边界，并且无法对不同绘制缩放下的最终整数鼠标路线提供可靠回退。

复核当前代码得到以下事实：

1. 阶段二的 `RouteRegionType`、`JunctionPort` 和图边证据仍是 `ImageProcessor.cpp` 内部临时数据。`ProcessedImage` 中没有原方案所写的持久 `ValidatedRouteGraph`，只有优化后的 `DrawingPath`。
2. `DrawingPath::sourceEdgeEnds` 只保存每笔中的点索引。`PathOptimizer` 在连接、反转和重排图边时会维护这些结束索引，但不会携带区域类型、端口身份、闭环接缝或角点标记。
3. 当前 `TraceSkeleton` 只给整条图边统计一个占优区域类型，没有在细线、粗笔触、紧凑填充轮廓和交叉区的实际切换位置分段。因此不能仅根据已有 `sourceEdgeEnds` 宣称“拟合绝不跨越区域边界”。
4. 原建议把 `VectorStroke::sourceEdgeEnds` 改成矢量段索引，但一条源图边可能拟合成多个直线／贝塞尔段，也可能局部回退为多段原折线。只保存一个矢量段索引会丢失源点范围和反转关系。
5. 原方案只验证浮点拟合曲线，然后在用户缩放后采样。`0.30×`、`1.00×` 和 `3.00×` 的整数化结果并不等价；低缩放会合并点，高缩放会增加采样，可能在某个尺度产生新折返、自交或锚点偏移。必须在每次重建 `ExecutionPlan` 时进行尺度相关门禁并允许局部回退。
6. 当前路线预览已经正确地从 `ExecutionPlan` 的左键按下命令重建，真实输入也消费同一个计划。这一链路不需要推翻；阶段三只能增加矢量输入重载，不能增加独立的“漂亮曲线预览”路径。
7. 阶段三原验收项包含微软画图和VRChat真实绘制。代码、自动测试和离线诊断全部通过后只能称为“实现完成、待实绘验证”，在两类实绘完成前不能默认启用。

修订后的阶段三先增加一个**零几何变化的元数据固化子阶段**：从阶段二图边生成区域跨度和硬锚点，在 `PathOptimizer` 反转、连接和重排时同步映射。该子阶段必须证明14张样本的阶段二折线、`ExecutionPlan` 命令和执行覆盖逐字节不变。之后的拟合和每尺度执行采样只消费这份已固化元数据，不能重新从预览图猜测端口或区域类型。

### 1.5 阶段三实施结果

修订后的阶段3A～3D和目标环境实绘验收均已完成。以下是先完成的离线实现与验证结果：

- `DrawingPath::routeMetadata` 持久保存连续 `RouteSpan`、区域类型、图端点、交叉端口、区域边界和闭环接缝；阶段3B检测出的受保护尖角保存在拆分后的矢量跨度两端。`PathOptimizer` 在图边连接、正反向遍历、闭环旋转和空笔重排时同步换算阶段二元数据；14张样本在添加／移除元数据时生成的阶段二 `ExecutionPlan` 命令逐项相同。
- 新增 `VectorPath.cpp`。拟合仅发生在硬锚点之间，开放跨度先按端点字典序规范方向拟合；反向执行只反转已拟合曲线和控制柄，不重新拟合。缓弯、S形、长斜线和尖角合成测试覆盖直线／三次贝塞尔、尖角分段以及浮点正反向严格逆序。
- 每个拟合跨度保存阶段二 `fallbackPolyline`。浮点候选需要同时通过端点、双向距离、墨迹支持、控制柄方向、包围盒和自交门禁；`Junction`、`Ambiguous`、过短或不能减少折线段的跨度直接保留阶段二折线。
- `BuildExecutionPlan` 增加矢量重载。在最终 `effectiveMouseScale` 下以De Casteljau自适应细分，再检查整数端点、双向偏差、墨迹支持、自交和高频方向折返；失败只回退当前跨度。合成测试证明正反向整数采样及最大单步拆分严格互为逆序，并证明越出墨迹的人工错误贝塞尔会局部回退。
- 主界面仍从最终 `ExecutionPlan` 重建路线预览，绘制线程消费同一计划。便携设置 `vector_path_enabled=1` 默认启用阶段三；设置为0可恢复阶段二折线，未新增普通用户控件。

14张样本共包含31,309个阶段二区域跨度，尖角分段后为33,576个；其中8,235个跨度通过浮点拟合门禁，其余跨度保持阶段二折线。在实际绘制尺度门禁下：

- `0.30×`：接受4,289个，局部回退3,946个；
- `1.00×`：接受7,275个，局部回退960个；
- `3.00×`：接受6,249个，局部回退1,986个。

完整诊断位于被Git忽略的 `build/lineart-stage3-final-verified`，包含全部14张 `vector-route.bmp` 和三种缩放的 `execution-route`。并排人工检查没有发现阶段二轮廓缺失、新增毛刺或跨墨迹连接；路线越出规范墨迹比例仍为0，组件覆盖率仍为100%。两次Release最终复测的阶段三路径处理耗时中位数为492.5～536 ms、P95为762～800 ms，完整测试进程峰值工作集129.3 MB，低于160 MB目标。

离线图片不能代替真实绘制。用户已完成本版目标环境实绘并明确确认效果可用，因此0.2.0将阶段三设为默认；若后续在特定程序中发现兼容问题，可通过软件目录内的 `vector_path_enabled=0` 恢复阶段二折线。

## 2. 阶段一实施前的问题验证结论

实施前的新增样本已经证明：

- 路径越出线稿比例可以是 0，但眼睛和密集交叉处仍然存在星状毛刺。
- 连通组件覆盖率可以是 100%，但组件内部的路径形状仍可能错误。
- `optimized-route.bmp` 在鼠标整数坐标量化前已经存在错误枝条，因此问题不只来自 `SendInput`。
- 当前线稿保存为二值像素，预览和导出时再放大，斜线和曲线会保留明显台阶。
- 当前线稿掩码统一进行一次闭运算，距离很近的两条线可能被错误连接。
- 当前 SVG 按每一行的黑色像素输出矩形，并不是真正的矢量线稿，放大后仍能看到像素结构。

因此，下面这些指标只能作为安全约束，不能单独代表质量合格：

- 路径位于线稿墨迹内。
- 连通组件覆盖率为 100%。
- 路径点数增加或减少。
- 预览使用了双线性过滤或抗锯齿绘制。

最终结论必须由规范线稿、浮点路线、最终鼠标执行路线和人工对比共同得出。

## 3. 新的完整处理链路

```text
原图 BGRA
  → 透明区域合成到白底
  → 感知灰度与轻量保边降噪
  → PS式反相／高斯模糊／颜色减淡
  → 暗线脊响应与RGB颜色边界补充
  → 非极大值抑制＋双阈值连接
  → 方向约束的防粘连和有限补线
  → CanonicalLineArtExtraction
        ├─→ 灰度覆盖线稿 → 预览、PNG、矢量SVG
        ├─→ 二值拓扑掩码
        └─→ 临时像素证据：置信度／切线／尺度位图／来源标记
                  ↓
      拓扑掩码＋临时证据＋墨迹内距离场
        → 局部区域分类
        → 交叉端口图、毛刺判定和受墨迹支持的内部连接
        → 阶段二验证路线（概念质量边界；当前尚非持久C++对象）
        → 无损图边分解与空笔顺序优化
        → 按结构边界分段的直线／三次贝塞尔拟合
        → 应用绘制缩放后的自适应采样和确定性整数化
        → 唯一 ExecutionPlan
        → 路线预览与真实鼠标执行
```

预览线稿和路径分析不能再分别运行两套互不相关的提取算法。灰度覆盖图、拓扑掩码和临时证据必须来自同一次 `CanonicalLineArtExtraction`：灰度覆盖图保留平滑边缘和原始线宽，拓扑掩码限定可绘制区域，临时证据用于判断像素与分支是否可靠。这里的“阶段二验证路线”是概念上的质量边界，并不是当前已经持久化的 `ValidatedRouteGraph` C++对象；阶段三不得绕过该验证结果重新从二值像素生成路线。

## 4. 参照 Photoshop 的线稿提取

### 4.1 对应的 Photoshop 思路

常见的 Photoshop 线稿提取步骤为：

1. 合并可见效果并去色。
2. 复制灰度图层并反相。
3. 对反相图层应用高斯模糊。
4. 使用“颜色减淡”混合，使局部暗线相对背景被强调。
5. 使用色阶或曲线压白背景、加深有效线条。
6. 必要时使用蒙版清理噪点和错误连接。

VRC-Draw 不模拟 Photoshop 的图层界面，而是直接计算等价响应。设归一化灰度为 `G∈[0,1]`，黑色为0、白色为1：

```text
Iσ = GaussianBlur(1 - G, σ)
Dσ = clamp(G / max(1 - Iσ, ε), 0, 1)
Pσ = 1 - Dσ
```

`Pσ` 是该尺度的线稿强度。它本质上比较当前像素与局部背景亮度，能像 Photoshop 的颜色减淡流程一样压白大面积平缓色块，同时突出深色轮廓。

### 4.2 多尺度而不是单一模糊半径

单一高斯半径无法同时处理细睫毛、普通轮廓和粗眼线。程序应根据 `processingScale` 计算三档尺度，例如：

```text
σfine   = 0.7 × processingScale
σnormal = 1.4 × processingScale
σcoarse = 2.8 × processingScale
```

具体数值必须由全部样本验证后确定，不能作为用户设置。融合时：

- 细尺度负责睫毛、发丝和衣物纹理。
- 中尺度负责普通角色轮廓。
- 粗尺度只用于判断粗线和局部背景，不直接把阴影纹理全部加入线稿。

阶段一已经使用三尺度响应生成正确线稿，但目前只保留三个尺度的最大值。阶段二必须在不改变阶段一灰度覆盖图和拓扑图的前提下，同时记录每个像素的响应强度、主方向和三位尺度支持位图，不能只剩0/1二值图。

### 4.3 与暗线脊和颜色边界融合

PS式颜色减淡是主要线稿来源，但彩色插画中存在亮度接近、颜色不同的边界，仅看灰度会漏线。因此还需要两种受控补充：

- 暗线脊响应：补充颜色减淡没有稳定检测到的深色中心线。
- RGB主梯度：补充亮度接近但色相明显不同的轮廓。

RGB边界必须先进行非极大值抑制，只保留梯度峰值的一侧，禁止再次产生双边线。阴影渐变、皮肤红晕和大面积纹理不能因为有颜色变化就自动成为线稿。

### 4.4 自动色阶与双阈值

Photoshop 的色阶操作改为基于响应直方图的自动黑白点和伽马调整：

- 忽略透明背景和纯白背景的大峰值。
- 使用有效响应分位数计算黑点和白点。
- 限制最大增益，避免把压缩噪声放大成线条。
- 根据线稿图、平涂插画和彩色复杂插画的自动分类选择受限参数范围。

之后使用强、弱两个阈值：

- 强响应直接成为可靠线稿核心。
- 弱响应只有与强核心在位置和切线方向上连续时才保留。
- 不能只因为8邻域接触就让弱响应扩散到另一条近邻线。

### 4.5 按输入类型选择主来源

不能对所有图片无条件套用完全相同的颜色减淡强度：

- 原生黑白或低彩度线稿：以原始灰度覆盖和局部暗度为主，PS式响应只用于补充低对比度淡线，避免改变已经正确的线宽。
- 平涂彩色插画：以PS式响应和受控RGB边界为主，抑制色块内部渐变。
- 复杂渐变插画：提高可靠响应门槛，优先保留结构轮廓，避免把光影和皮肤纹理全部转成线条。

分类只决定内部算法组合，不增加用户可见的模式选项。每个输入分支都必须在当前样本中单独回归，不能为了改善彩色图片而降低原生线稿质量。

## 5. 消除线稿锯齿

### 5.1 分离灰度覆盖图与二值拓扑图

阶段一实施前的 `BinaryImage` 只有0和1，无法保存亚像素覆盖。阶段一已经落地的公开数据为：

```cpp
struct GrayImage {
    std::uint32_t width{};
    std::uint32_t height{};
    std::vector<std::uint8_t> pixels; // 0=白，255=完全黑，保留中间覆盖值
};

struct LineArtDocument {
    GrayImage coverageLineArt;
    BinaryImage cleanLineArt;
    DrawingPath strokes;
};
```

- 线稿预览和 PNG 使用 `coverageLineArt`，保留灰色边缘像素。
- 路径拓扑只使用从同一响应生成的 `cleanLineArt`。
- 两者轮廓位置一致，但用途不同。
- 禁止把平滑后的路线反向渲染成线稿，线稿仍然保留原始线宽。

阶段二增加的证据不能塞进 `coverageLineArt`，而应由内部提取结果临时携带：

```cpp
enum LineEvidenceFlags : std::uint8_t {
    StrongCore    = 1 << 0,
    OriginalDark = 1 << 1,
    RgbBoundary  = 1 << 2,
    RepairedGap  = 1 << 3,
};

struct LinePixelEvidence {
    std::uint8_t confidence{}; // 自动色阶和82%显示下限之前的结构置信度
    std::uint8_t tangentBin{255}; // 0～15表示[0,π)方向，255表示无可靠方向
    std::uint8_t scaleMask{};  // bit0/1/2分别表示细／中／粗尺度支持
    std::uint8_t flags{};
};

struct CanonicalLineArtExtraction {
    GrayImage coverage;
    BinaryImage topology;
    std::vector<LinePixelEvidence> evidence;
};
```

`evidence` 只活到阶段二路线构建完成，不写入 `ProcessedImage`，不进入设置、导出文件或用户界面。这样既能保留判断毛刺所需证据，也不会让每张已导入图片永久增加内存占用。

### 5.2 亚像素边界与降采样

二值掩码边缘不能直接放大。应在连续响应上估计阈值等值线的亚像素位置，并使用以下任一等价实现生成覆盖率：

- 2×临时超采样后使用面积过滤降采样。
- 基于局部响应梯度计算像素覆盖率。
- 对等值线使用自有扫描转换器计算覆盖率。

预览纹理必须使用灰度覆盖值创建，D3D线性过滤只作为缩放辅助，不能代替源数据中的抗锯齿。

### 5.3 PNG与SVG导出

- PNG 从灰度覆盖线稿渲染，不再从0/1掩码直接放大。
- SVG 使用亚像素等值线生成闭合 `<path>`，保留墨迹外轮廓和孔洞。
- SVG 不再按每一行输出大量 `height="1"` 的像素矩形。
- SVG路径可以进行受边界误差约束的简化，但不得粘合两个独立组件。
- PNG、SVG和主界面线稿预览必须使用同一规范线稿响应进行对比验证。

## 6. 消除线稿粘连

### 6.1 取消全图无条件闭运算

阶段一实施前的“膨胀后腐蚀”全图闭运算可能跨过1～2像素空隙，因此已经从规范线稿生成流程中移除。它不能简单替换为更小的固定半径，因为不同分辨率和局部线宽下的效果不一致。

### 6.2 只允许方向一致的有限补线

候选断点只有同时满足以下条件才允许连接：

1. 两端距离小于与处理尺度、局部线宽相关的阈值。
2. 两端切线彼此相向，夹角在允许范围内。
3. 连接走廊中存在连续但较弱的原始响应。
4. 走廊不会穿过另一条线，也不会把两个平行轮廓粘在一起。
5. 连接前后不会产生新的三分支或更高阶节点。

任一条件失败就保留断开状态。

### 6.3 检测并切断错误桥

对已经连接的区域检测“窄桥”：

- 桥宽明显小于两侧局部线宽。
- 桥的响应强度显著低于两侧主线。
- 桥方向与两侧主线方向不连续。
- 在更高阈值或半尺度响应中桥消失，而两侧结构仍存在。

只有同时满足多项证据才切断，避免误删真正的X形交叉、睫毛连接和衣物缝线。切断后必须重新检查组件，小组件不能仅因被切断就自动删除。

如果原始高置信度线稿本身就是连续黑线，程序不能仅凭视觉猜测强行拆开；这类真实接触在线稿页保持原样，在路线阶段通过切线配对决定穿越关系。自动切断只处理算法阈值扩张、全图闭运算或弱响应桥造成的新增粘连。

### 6.4 近邻平行线保护

眼睛、发夹、衣领和头发中经常存在距离很近的平行线。程序应根据局部梯度法线和切线把它们识别为两条独立脊线：

- 沿法线方向存在两个稳定峰值时保持分离。
- 不能用连通组件数量判断它们是否属于同一线条。
- 后续骨架化和路径优化也不能在两条线之间添加跨空白连接。

## 7. 路径生成前的区域分类

平滑线稿并不自动得到正确路线。路径生成前必须根据内部距离、长宽比、主方向稳定性和局部拓扑，把墨迹划分为以下类型。

阶段二不能在现有 `BuildRouteSkeleton` 结果后再做分类。必须替换当前“全图半径中位数 → 单一 `filledRadius` → 所有粗区统一轮廓化”的流程：

1. 对 `cleanLineArt` 只计算一次墨迹内距离场，得到局部半线宽。
2. 用高、低两个局部宽度阈值形成粗区种子和受约束扩展区，阈值随 `processingScale` 和邻域宽度变化，不使用一张图片共用的粗区半径。
3. 对每个粗区片段计算面积、周长、协方差主轴、长宽比、距离场脊线长度、孔洞数以及与细线相接的端口数。
4. 分类发生在局部粗区片段上，而不是直接按整个8连通墨迹组件分类；眼线与睫毛、瞳孔与高光等相连结构仍可得到不同区域类型。
5. 分类置信度不足时保留阶段一拓扑，并输出调试标记，不允许回退到全局 `filledRadius` 规则。

### 7.1 普通细线

- 使用受距离场和像素证据约束的稳定中心线。
- 交叉处保留进入方向、源响应强度、尺度位图和来源标记。
- 不直接把每个骨架像素邻接关系视为最终图结构。

### 7.2 细长粗笔触

例如发夹、粗直线和长条眼线：

- 使用受边界约束的单条主中心线。
- 通过截面宽度和主方向判断它是“粗笔触”，而不是填充块。
- 禁止输出完整矩形或双边轮廓。

### 7.3 紧凑填充块

例如实心瞳孔、圆点和黑色图案：

- 使用外轮廓和真实孔洞轮廓。
- 不生成内部中轴树。
- 不因局部凹陷产生星状放射线。

### 7.4 多条线真实交叉

- 保留每条进入分支的切线和来源。
- X形交叉优先将方向最连续的四个分支配成两条穿越曲线。
- T形和Y形结构保留真实终止关系。
- 不能把所有分支无条件拉到一个最小二乘公共点。

分类置信度不足时保留局部调试标记并使用保守表示，但“保守”不等于回退到已经确认有毛刺的中轴树。

## 8. 错误拓扑和毛刺修复

这一步必须发生在无损笔画合并和矢量拟合之前。

阶段二应整体替换当前 `BuildRouteSkeleton` 中的半分辨率 `stableSupport` 和 `TraceSkeleton` 中的交叉簇合并、簇内边删除、最小二乘公共点拟合。旧实现只保留为基线对照和局部失败时的调试数据，不能成为新算法的回退结果。

### 8.1 区分可靠节点与候选错误节点

此前方案要求所有端点和交叉点原位保留，这会保护错误毛刺。新方案只保护经过验证的结构节点：

- 在多尺度响应中稳定存在。
- 具有明确的源线稿脊或边界支持。
- 与相邻分支切线连续。
- 不属于粗填充区域的中轴伪分支。
- 如果来自阶段一方向补线，必须同时满足补线走廊证据，不能与原生强线享有相同保护等级。

`sourceEdgeEnds` 只是路径来源边界，不是视觉正确性的证明，不能用来保护已经判定为错误的图边。

### 8.2 短毛刺删除

短终端分支只有同时满足以下条件才作为毛刺删除：

- 测地长度接近或小于局部线宽的若干倍。
- 相比同节点其他分支明显更短。
- 半尺度和更高阈值下缺少稳定支持。
- 方向表现为骨架角平分线、反向折返或轮廓凹陷产生的伪分支。
- 端点附近没有独立的强响应结构。

睫毛、发丝和衣物短线只要跨尺度稳定且有独立源响应，就不能仅因长度短而删除。

毛刺判定使用分支上的证据统计，而不是当前“半分辨率骨架附近是否有像素”的单个布尔值。至少记录低置信度比例、三尺度支持比例、原生强线比例、补线比例和端点置信度；只有多项证据共同指向伪分支时才删除。

### 8.3 交叉点切线配对

交叉簇不能先压成一个公共节点。应先在交叉区域边界上建立 `JunctionPort`：每条骨架分支离开交叉区域的位置形成一个端口，端口保存向外切线、局部宽度、置信度、尺度支持和原始折线路径。然后对端口求最小弯曲代价的配对：

- 四分支优先得到两条连续穿越路径。
- 三分支根据响应、端口夹角和真实终止证据区分T形与Y形；T形只让最连续的一对穿越，第三支连接到受支持的位置。
- 多余且不稳定的短分支先进入毛刺判定。
- 候选交点必须同时位于配对分支的正向有效射线范围、交叉墨迹区域内部和允许误差范围，禁止沿切线反向延长后形成突出尾巴。
- 五分支及以上不能全部拉到一个中心点；先根据端口切线和交叉区域内部连通性拆成多个局部穿越或终止关系。

每一对端口只允许使用两类内部连接：通过全部有效性检查的直线交点连接，或完全位于交叉墨迹区域中的最短受支持像素测地线。禁止使用当前的无条件最小二乘公共点。

### 8.4 阶段二的保守回退

局部修复失败时回退到“阶段二中最近一次通过验证的端口图或受支持测地线”，不能回退到当前已确认会产生毛刺的中轴树，也不能为了维持组件覆盖率随意补一条直线。

回退后仍必须满足：

- 不跨越 `cleanLineArt` 允许区域；
- 不新增端点、分支或组件连接；
- 不删除具有强原生证据的端口；
- 不改变阶段一的 `coverageLineArt` 和 `cleanLineArt`；
- 将失败区域写入 `junction-debug`，供样本回归和人工检查。

## 9. 阶段二元数据固化与受线稿约束的矢量拟合

### 9.1 零几何变化的元数据固化

阶段三实施前不能假定已经存在持久的 `ValidatedRouteGraph`。实际实现先让阶段二路线构建返回“折线＋跨度元数据”，再运行现有无损图边分解和空笔顺序优化：

```text
阶段二验证图边＋区域类型＋端口／闭环锚点
  → 按实际区域类型变化切分 RouteSpan
  → 无损图边分解／共享端点合并／反转／空笔顺序优化
  → 同步映射 RouteSpan 和硬锚点
  → 与当前阶段二 DrawingPath／ExecutionPlan 逐字节零差异
  → 固化的 ValidatedDrawingPath
```

`RouteSpan` 至少记录优化后笔画中的源点起止索引、区域类型和两端硬锚点标记。硬锚点包括阶段二图边端点、交叉端口、区域边界、闭环接缝和真实终止点。`PathOptimizer` 反转一条边或整笔时必须同时反转跨度顺序、换算点索引并交换左右锚点，禁止事后按坐标近似匹配。

元数据固化不得改变任何路线点。进入拟合前必须验证：

- 阶段二 `DrawingPath` 的每个点和每条线段完全不变；
- 优化前后逻辑线段多重集和最终执行覆盖继续完全一致；
- 每个跨度首尾索引合法、连续覆盖对应笔画，硬锚点坐标与阶段二折线逐点一致；
- 14张样本的阶段二路线图和 `ExecutionPlan` 命令逐字节相同。

### 9.2 分段直线与三次贝塞尔拟合

只有9.1节门禁通过后才能拟合：

```text
ValidatedDrawingPath
  → 尖角和结构节点分段
  → 平直区拟合直线
  → 连续弯曲区拟合三次贝塞尔
  → 局部响应与墨迹边界验证
  → 每个跨度保存已验证曲线和原阶段二回退折线
```

拟合片段不得跨越：

- 已验证的端点和交叉点；
- 用户可辨认的尖角；
- 闭环边界和选定起点；
- 细线、粗笔触和填充轮廓之间的类型边界。
- 任一 `RouteSpan` 或硬锚点边界；即使多条图边被合并到同一笔画，也必须分别拟合。

用户可辨认的尖角在每个 `RouteSpan` 内按转角、两侧测地长度和局部线宽自动检测，并写成新增硬锚点。检测必须在原阶段二折线上完成；不得先平滑再判断尖角。闭环使用阶段二已经选择的接缝作为固定起点，禁止为了拟合方便移动闭环接缝。

每条候选曲线必须满足：

1. 与规范中心线或轮廓的双向最大距离低于局部阈值。
2. 曲线位于允许墨迹区域内。
3. 控制柄不反向、不越过相邻结构节点。
4. 不产生自交、过冲或新的曲率尖峰。
5. 端点和结构切线满足局部连续性。

这里的局部回退只恢复经过第8节验证的正确折线，不再恢复未经修正的星状毛刺。

拟合必须与遍历方向无关。开放跨度先按端点字典序选择规范方向进行拟合，闭环使用固定接缝和固定方向；需要按相反方向执行时，只交换三次贝塞尔的 `p0↔p3`、`p1↔p2` 并反转段序，禁止对反向点列重新拟合。正向和反向曲线采样必须互为严格逆序。

现有 `PathOptimizer` 的“逻辑线段多重集和执行覆盖完全相同”门禁继续保留，但它只比较阶段二图边与无损重排结果。矢量拟合会有意改变折线采样点，因此改用以下独立门禁，不能拿拟合结果再次通过“逐线段完全相同”检查：

- 端点、交叉端口、尖角和区域边界逐点不变；
- 曲线与阶段二验证折线的双向最大距离受限；
- 曲线采样全部位于规范墨迹允许区域；
- 组件、闭环、自交数和端口连接关系不变；
- 不产生控制柄反向、曲率尖峰或包围盒外过冲。

每个通过门禁的拟合跨度仍保存对应的阶段二折线。这样后续某个绘制缩放下的整数采样失败时可以只回退该跨度，而不是让整张图回退或重新运行图片处理。

## 10. 最终鼠标执行采样

三次贝塞尔不能直接交给 `SendInput`。阶段三为 `BuildExecutionPlan` 增加矢量路线输入重载；现有折线重载继续保留，作为阶段二零差异基线和局部回退实现。应用用户的 `drawingScale` 与最长边限制得到最终 `effectiveMouseScale` 后，逐个拟合跨度使用 De Casteljau 自适应细分，直到同时满足：

- 曲线对弦的最大偏差低于最终绘制尺度的误差阈值。
- 相邻采样点不超过落笔最大单步。
- 尖角、端点和交叉结构恰好成为采样点。
- 量化后没有连续重复点或反向抖动。

整数化必须保持正反向一致。推荐先按固定参数方向得到绝对浮点采样点，以笔画起点为锚进行确定性舍入，再在需要反向绘制时反转同一组整数点；禁止使用会因遍历方向不同而改变结果的逐步误差扩散。相邻整数点超过最大单步时，再使用现有方向对称插值拆分。

### 10.1 每个绘制尺度的执行门禁

浮点曲线通过第9节门禁不代表所有鼠标缩放都安全。每次用户修改绘制大小并重建 `ExecutionPlan` 时，程序必须在同一个 `effectiveMouseScale` 下同时生成：

1. 拟合跨度的候选整数采样点；
2. 该跨度保存的阶段二回退折线的基线整数采样点。

候选只有同时满足以下条件才进入计划：

- 首尾硬锚点与基线整数坐标完全相同，锚点顺序不变；
- 删除连续重复点后仍不新增端点、回头段、自交或跨跨度连接；
- 相对阶段二折线的最大偏差受当前缩放和局部线宽共同限制；
- 映射回图片坐标后的采样和相邻连线仍位于 `cleanLineArt` 允许区域；
- 高频方向翻转数和离散曲率尖峰数不高于同尺度基线；
- 正向与反向结果互为严格逆序，最大单步拆分后仍成立。

任一条件失败就只把该跨度的阶段二基线整数路线写入 `ExecutionPlan`，相邻已通过跨度不受影响。`ExecutionPlanMetrics` 应分别记录拟合跨度数、接受数、尺度回退数和最终落笔采样数，测试不能只比较整图是否“看起来更平滑”。点状笔画或在低缩放下全部量化到同一坐标的跨度沿用现有独立落笔语义，不伪造移动命令。

预览与真实输入继续共同消费唯一的 `ExecutionPlan`；主界面路线页必须从左键按下期间的最终命令重建，不能直接显示更漂亮的浮点贝塞尔曲线。浮点 `vector-route.bmp` 只用于开发诊断，不能作为用户实际绘制效果。代码与自动门禁通过后先保留内部回退开关；微软画图和VRChat实绘都确认后才能默认选择矢量输入重载。

必须接受一个物理限制：最终鼠标坐标是整数，斜线在1像素放大的调试图中仍会具有基本栅格台阶。算法需要消除的是方向来回抖动和多余折点，不能承诺在任意低绘制尺寸下得到无限平滑的像素边缘。

## 11. 建议数据结构

```cpp
enum class LineRegionType : std::uint8_t {
    ThinLine,
    ElongatedThickStroke,
    CompactFill,
    Junction,
    Ambiguous,
};

struct JunctionPort {
    PointF point;
    PointF outwardTangent;
    float localRadius{};
    std::uint8_t confidence{};
    std::uint8_t scaleMask{};
};

enum RouteAnchorFlags : std::uint8_t {
    AnchorNone           = 0,
    AnchorGraphEndpoint  = 1 << 0,
    AnchorJunctionPort   = 1 << 1,
    AnchorRegionBoundary = 1 << 2,
    AnchorClosedSeam     = 1 << 3,
    AnchorProtectedCorner = 1 << 4,
};

struct RouteSpan {
    std::size_t pointBegin{}; // 优化后Stroke中的闭区间
    std::size_t pointEnd{};
    LineRegionType regionType{};
    std::uint8_t beginAnchorFlags{};
    std::uint8_t endAnchorFlags{};
};

struct StrokeRouteMetadata {
    std::vector<RouteSpan> spans;
    bool closed{};
};

// 实际实现把元数据直接附在DrawingPath中，避免复制完整阶段二折线：
// std::vector<StrokeRouteMetadata> DrawingPath::routeMetadata;

enum class VectorSegmentType : std::uint8_t {
    Line,
    CubicBezier,
};

struct CubicBezier {
    PointF p0;
    PointF p1;
    PointF p2;
    PointF p3;
};

struct VectorSegment {
    VectorSegmentType type{};
    PointF lineEnd{};
    CubicBezier cubic{};
};

struct FittedRouteSpan {
    PointF start{};
    std::vector<VectorSegment> segments;
    Stroke fallbackPolyline; // 同一跨度的阶段二验证折线
    LineRegionType regionType{};
    std::uint8_t beginAnchorFlags{};
    std::uint8_t endAnchorFlags{};
    bool fitted{}; // false时直接使用fallbackPolyline
};

struct VectorStroke {
    std::vector<FittedRouteSpan> spans;
    bool closed{};
};

struct VectorDrawingPath {
    std::uint32_t width{};
    std::uint32_t height{};
    std::vector<VectorStroke> strokes;
};
```

`LineArtDocument` 在阶段三期间继续保留现有阶段二 `DrawingPath strokes` 作为诊断和整图安全回退，并增加可选的 `VectorDrawingPath vectorPath`。实际实现将 `StrokeRouteMetadata` 直接存入 `DrawingPath::routeMetadata`，而不是再包装一个会复制完整折线的 `ValidatedDrawingPath`。用户正常修改绘制大小只重建执行计划，不重新提取图片或重新拟合。

第5.1节的 `LinePixelEvidence` 属于内部临时数据，不重复放入 `ValidatedDrawingPath`；只固化拟合所需的区域类型和锚点标记。`sourceEdgeEnds` 在兼容现有折线执行链路期间保留，但矢量拟合以 `RouteSpan` 为准，不能同时维护两套相互矛盾的边界语义。`fallbackPolyline` 只复制阶段二最终路线点，按当前样本规模远小于图片证据缓冲区；仍应测量实际内存，而不是提前删除回退数据。

必须增加以下合成图片：

- 实心圆和实心椭圆，验证生成轮廓而不是星状中轴。

- X、T、Y、锐角交叉和密集多线交叉。

- 切线延长交点位于某一分支反向射线的结构，验证拒绝该交点且不产生突出尾巴。
- 与紧凑填充块相接的细线和与细长粗笔触相接的短线，验证局部分类不会按整个组件误判。

### 12.4 自动指标

自动验收至少包括：

- 线稿灰度边缘包含稳定的中间覆盖值，不是放大的纯二值台阶。
- 阶段二增加临时证据后，14张样本的 `coverageLineArt` 和 `cleanLineArt` 必须与阶段一最终结果逐字节相同。
- 标注为独立的近邻线保持分离，错误粘连数量相对当前基线下降到0。
- 受保护细节、可靠端点和可靠组件覆盖率为100%。
- 紧凑填充测试内部没有中轴端点和星状分支。
- 细长粗笔触测试只生成一条主轴，不生成完整矩形轮廓。
- 路径不跨越规范线稿允许区域。
- 人工标注的毛刺区域中不再出现错误终端分支。
- 交叉端口数量、配对关系和连接方向符合合成测试标注，不存在反向射线交点。
- 阶段二输出的组件、闭环和受保护端点数量不能因无损图边分解而改变。
- 最终执行路线相对当前基线减少高频方向翻转和不必要曲率尖峰。
- `0.30×`、`1.00×`、`3.00×` 均分别统计接受／回退跨度，所有硬锚点与同尺度阶段二基线一致。
- 同一拟合跨度正向与反向采样、整数化和最大单步拆分结果严格互为逆序。
- PNG、SVG和主界面线稿在相同尺寸下轮廓位置一致。

阶段二有意修改路线，因此“阶段二路线与阶段一旧路线逐字节相同”不是通过条件；但阶段一线稿已经验收，阶段二不得再改动灰度覆盖图和二值拓扑图。阶段三有意平滑已验证折线，因此“矢量拟合前后逻辑线段完全相同”也不是通过条件；现有无损优化器内部的零差异门禁仍必须通过。每一阶段都要保存上一个阶段输出作为对照，证明变化只发生在本阶段目标上且没有丢失其他细节。

## 13. 性能与存储约束

- 继续使用最长边1536、最多240万处理像素作为第一轮基线，不在没有数据前盲目提高分辨率。
- 高斯模糊使用可分离卷积或等价线性实现，时间复杂度接近 `O(N × radius)`。
- 三个尺度顺序计算并复用浮点缓冲区，避免同时保留三份完整 `float` 图。
- 240万像素下单个 `float` 缓冲区约9.6MB，单个8位响应或掩码约2.4MB。
- 四字节 `LinePixelEvidence` 在240万像素下约9.6MB；它只在规范线稿提取到阶段二路线完成之间存在，随后立即释放。
- Release峰值工作集目标不超过160MB；若超过，先优化缓冲区生命周期，不能降低样本质量换取内存。
- 调试图片默认只在测试环境生成，不进入发布包。
- 用户正常使用仍只保存设置和主动导出的线稿，所有文件位于软件目录内。

具体处理耗时必须在14张样本上记录中位数、P95和峰值内存后再确定验收上限，不能在实施前编造固定性能结论。

阶段二完成后的MinGW Release实测为：正常图片处理耗时中位数499.5 ms、P95为777 ms，完整测试进程峰值工作集128.5 MB。测试模式显式请求诊断时会额外保留并写出多张8位证据图；正式应用传入空调试指针，不产生这些文件，也不把临时证据保存在用户图片对象中。

阶段三路径在同一批14张样本上的两次MinGW Release最终复测为：处理耗时中位数492.5～536 ms、P95为762～800 ms，完整测试进程峰值工作集129.3 MB。兼容开关关闭时不生成或保存 `VectorDrawingPath`，直接恢复阶段二的处理和内存路径。
