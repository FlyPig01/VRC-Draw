# VRC-Draw 分辨率验证与路径质量改进方案

验证日期：2026-07-26

## 1. 文档目的

本文档先记录分辨率受控验证，再记录对应方案的正式实施结果。前半部分的768流程和A/B数据作为实施前基线保留，用于说明修改依据；截至2026-07-26，文档第8节所述核心方案已经落地并通过回归测试。

本文中的12张样本数字是2026-07-26该阶段执行时的固定历史结果，不应替换为当前样本数。截至2026-07-27，仓库的 `sample` 目录已有14张图片；最新阶段二／阶段三结果见[线稿与真实绘制路径质量改进方案](VRC-Draw-真实绘制路径矢量拟合方案.md)。

初始验证回答以下问题：

1. 当前最长边 `768` 的内部工作分辨率是否造成明显质量损失。
2. 将工作分辨率提高到 `1536` 后，哪些问题得到改善。
3. 哪些问题与分辨率无关，不能通过简单提高常量解决。
4. 下一阶段应该怎样改进线稿和路径架构。

受控验证阶段没有直接保留 `1536` 常量修改；完成验证并确认执行尺度解耦方案后，现已正式将默认处理上限改为 `1536`。具体实施状态见第11节。

## 2. 实施前处理流程

实施前，程序在任何线稿提取之前先把输入图片最长边限制到 `768`：

```text
原始图片
→ WIC Fant 插值缩小到最长边 768
→ 灰度与颜色边界分析
→ 高斯模糊和二值化
→ 3×3 闭运算
→ 删除小连通组件
→ 得到线稿掩码
→ Zhang-Suen 骨架化
→ 交叉点和路径图提取
→ 鼠标执行计划
```

因此，线稿预览、路径生成和最终鼠标坐标都建立在缩小后的栅格上。UI放大预览和导出PNG只会放大已有掩码，不能恢复缩小时丢失的信息。

## 4. 定量结果

以下统计来自同一套12张样本。耗时和峰值内存是单次本地运行结果，只用于判断量级，不作为稳定性能基准。

| 指标 | 768组 | 1536/原始组 | 变化 |
|---|---:|---:|---:|
| 12张样本处理耗时 | 1.735秒 | 2.778秒 | +60.1% |
| 峰值工作集 | 30.6 MB | 76.5 MB | +150.0% |
| 总笔画数 | 7,144 | 10,624 | +48.7% |
| 总路径点数 | 181,266 | 336,494 | +85.6% |
| 线稿连通组件总数 | 915 | 1,740 | +90.2% |
| 平均线稿墨迹占比 | 13.45% | 10.93% | -2.52个百分点 |
| 最大路径越界率 | 0.4486% | 0.1401% | 明显降低 |

### 4.1 数据含义

- 高分辨率保留了更多彼此分离的细线和小结构，因此连通组件、路径点和笔画数明显增加。
- 平均墨迹占比下降，说明低分辨率下部分相邻线条会粘连或被形态学处理加粗。
- 路径越界率下降，说明交叉点拟合和骨架坐标在更高分辨率下有更大的几何余量。
- 组件数量增加不全部等于有效细节增加，其中也可能包含文字、噪点、纹理和错误颜色边界。
- 当前不压缩笔画，因此高分辨率会直接增加实际绘制时间。

## 5. 视觉验证结论

### 5.1 分辨率确实造成明显损失

`image(3).png` 从 `688×1504` 缩小到 `351×768` 后，低分辨率组存在以下问题：

- 头发内部的细线合并或断裂。
- 眼睛和睫毛结构变成较大的黑块。
- 衣服接缝、装饰和背景细节缺失。
- 大圆弧和长曲线出现更明显的像素折线。

恢复到原始分辨率后，这些结构明显增加，曲线也更连续。因此，最长边768是当前细节缺失的重要原因。

### 5.2 分辨率不是全部原因

`image(1).png` 的原始尺寸为 `472×657`，两组都没有缩放。两组线稿和路径文件的SHA-256结果完全一致。

这说明该图片中仍然存在的错误与768限制无关，只能来自：

- 线稿二值化。
- 固定像素形态学处理。
- 粗黑区域的骨架化。
- 交叉点和分支识别。

### 5.3 极小尺度变化也会改变拓扑

`屏幕截图 2026-07-25 140558.png` 在两组中的尺寸分别为：

```text
768组：768×761
1536组：772×765
```

线性尺寸只相差约0.5%，但线稿组件数从84变为86，路径笔画数从407变为403，部分小结构的连接方式也发生变化。

这说明当前算法存在尺度不稳定：固定的模糊半径、3×3闭运算、最小组件面积、交叉区域距离和切线采样长度没有随处理分辨率变化。

### 5.4 提高分辨率没有消除星状毛刺

高分辨率组中，眼睛、领口、阴影和密集交汇位置仍然可以看到星状或树枝状路径。

根本原因是当前流程把“有宽度的黑色区域”直接送入Zhang-Suen骨架化。骨架化计算的是区域的中轴，不理解它原本是：

- 一条粗笔触。
- 多条重叠轮廓。
- 一个填充阴影。
- 眼睛等封闭黑色图案。

粗黑区域的中轴天然可能是树形结构。提高分辨率只会让这棵中轴树更精确，不会自动把它变成用户期望的轮廓线。

## 6. 对此前质量指标的修正

此前使用的“组件覆盖率100%”和“路径越界率低于1%”只能作为安全约束，不能代表视觉质量合格。

- 组件覆盖率100%：只说明每个墨迹区域至少存在一条路径，不说明路径形状正确。
- 越界率低：只说明路径大多位于墨迹内部，无法识别墨迹内部的星状毛刺。
- 路径点更多：可能是有效细节，也可能是噪点和错误分支。

后续不能再用这些指标直接得出“质量已经满足要求”的结论。

## 7. 总体结论

1. 最长边768对高分辨率竖图损失严重，必须调整。
2. 1536组对细线、曲线和小型结构有明显改善。
3. 1536在当前测试机器上的峰值工作集约76.5MB，作为图片导入阶段的一次性处理可以接受。
4. 不能只把常量从768改成1536，否则实际鼠标绘制范围、路径点数和绘制时间也会同步增加。
5. 固定像素参数必须改为与分辨率和局部线宽相关的参数。
6. 粗黑区域不能继续直接使用普通骨架化，否则星状毛刺无法根治。
7. 线稿高分辨率处理和最终鼠标执行尺度必须解耦。

## 8. 改进方案与实施依据

### 阶段一：重构分辨率架构

引入内部的处理分辨率上下文，不增加普通用户设置：

```text
原始图片尺寸
→ 线稿处理尺寸
→ 浮点路径坐标
→ 鼠标执行尺寸
```

建议规则：

- 线稿处理默认使用原图，最长边内部限制为1536。
- 同时限制最大处理像素约为240万，避免极端宽图或超大图片消耗过多内存。
- UI线稿预览直接使用高分辨率线稿纹理。
- PNG和SVG导出使用真实高分辨率线稿，不再把768掩码放大伪装成原始尺寸。
- 路径一直保留浮点坐标。
- 在生成鼠标命令前单独应用执行比例，不能让处理分辨率从768提高到1536后，实际鼠标移动范围也意外翻倍。

当前 `BuildExecutionPlan` 默认 `mouseScale=1.0`，会直接把图片像素转换成鼠标相对移动量。因此，正式提高处理分辨率之前必须先完成执行尺度解耦。

### 阶段二：参数尺度化

建立统一的参考尺度和局部线宽估计，替换散落的固定像素常量。

需要调整的参数包括：

- 高斯模糊 `sigma`。
- 闭运算半径。
- 最小连通组件面积，面积阈值应按尺度平方变化。
- 图像边缘清理宽度。
- 切线采样长度。
- 相邻交叉簇合并距离。
- 毛刺长度阈值。
- 路径连接的墨迹容差。

优先使用距离变换得到的局部线宽，而不是只根据整张图片最长边缩放参数。

### 阶段三：区分细线和粗黑区域

路径生成前先对线稿区域分类：

#### 细线区域

- 使用灰度脊线或稳定中心线提取。
- 保留完整拓扑。
- 在交叉处拟合进入分支的切线。

#### 粗线和填充区域

- 不直接输出完整中轴树。
- 优先提取外轮廓和孔洞轮廓。
- 判断是否存在可确认的主笔触方向，只保留稳定主轴。
- 阴影排线属于以后阶段，本阶段不自动生成。

这样可以避免眼睛和阴影黑块被转换成星状树枝。

### 阶段四：多尺度稳定分支

同一线稿可以在原始尺度和半尺度各生成一次候选骨架：

- 两个尺度都存在的分支视为稳定真实结构。
- 只在单一尺度出现、且长度接近局部线宽的分支视为骨架毛刺候选。
- 删除候选前仍检查端点和连通关系，避免误删睫毛等真实短线。

这比单纯按固定长度删除短枝更可靠。

### 阶段五：路径矢量化与鼠标执行

- 高分辨率骨架先拟合为直线、圆弧或样条曲线。
- 几何误差以线稿坐标衡量，不以路径点数衡量。
- 缩放到鼠标执行空间后再进行采样。
- 使用浮点到整数的误差累计，减少连续取整造成的抖动。
- 路径预览继续直接来自最终执行命令。
- 本阶段仍不以减少笔画数为目标，只删除不会改变几何的重复采样点。

### 阶段六：质量验证体系

保留现有约束指标，但增加真正反映视觉质量的测试：

- 768与1536结果的尺度一致性。
- 路径到目标中心线的Chamfer距离。
- 关键轮廓召回率。
- 合成X、T、Y、V和锐角交叉的错误分支数。
- 粗黑圆形、眼睛和阴影块的星状分支数。
- 闭环数量和真实端点数量。
- 执行计划渲染与几何路径渲染的差异。
- 对固定样本保存人工确认的基准图，进行视觉回归。

组件覆盖率和越界率继续保留，但不得单独作为质量合格标准。

## 9. 性能与存储预期

### 运行时性能

根据本次验证：

- 1536处理耗时约为768的1.6倍。
- 峰值工作集约从30.6MB增加到76.5MB。
- 当前测试集仍能在约3秒内完成全量测试。

单张图片导入是异步的一次性操作，因此该开销可以接受。正式实现时仍应复用临时缓冲区，避免多个高分辨率浮点图同时长期存在。

### 软件体积和用户存储

- 不需要引入OpenCV、Qt或AI运行库。
- 继续使用WIC和现有C++实现，不明显增加发布包体积。
- 高分辨率线稿和路径默认只保存在内存中。
- 用户主动导出时才写入软件目录下的 `exports`。
- 所有文件继续遵守便携式目录规则，删除软件目录即可完全清除。

## 10. 实施顺序

1. 先解耦线稿处理尺寸和鼠标执行尺寸。
2. 将线稿处理上限提高到1536，并加入最大像素限制。
3. 将全部固定像素参数改为尺度和局部线宽自适应。
4. 重新生成12张样本的线稿，先确认线稿质量。
5. 对粗黑区域增加轮廓/主轴分类，避免直接生成中轴树。
6. 实现多尺度稳定分支和交叉点规范化。
7. 使用新的视觉指标和人工基准图验证。
8. 路径质量确认后，再讨论笔画数和绘制时间压缩。

没有单独实施“只把768改成1536”的修改。正式实现先完成处理尺度与执行尺度解耦，再接入粗黑区域分类、多尺度稳定性和受墨迹约束的路径处理。

## 11. 正式实施结果

实施日期：2026-07-26

### 11.1 高分辨率处理与资源上限

`ImageProcessingOptions` 现在提供内部配置，普通用户界面不增加新选项：

```cpp
struct ImageProcessingOptions {
    std::uint32_t maximumDimension{1536};
    std::uint64_t maximumPixels{2'400'000};
};
```

解码阶段同时计算最长边比例和总像素比例，并采用两者中更严格的限制。常规样本默认使用最长边1536；极端宽图、长图或超大图片仍受240万像素上限保护。线稿预览、PNG/SVG导出和路径提取全部使用新的高分辨率结果。

没有机械放大所有图像滤波参数。受控实验发现，将高斯模糊和3×3闭运算同步放大到2像素会重新粘连高分辨率细线，因此以下参数保持质量优先的固定小半径：

- 细线高斯模糊 `sigma=0.65`。
- 颜色边界模糊 `sigma=1.0`。
- 闭运算半径1像素。
- 受保护墨迹扩张半径2像素。

连通组件面积、图像边缘清理、颜色扫描边距、交叉点合并距离、切线采样长度、毛刺长度和局部线宽探测范围则按处理尺度换算。

### 11.2 鼠标执行尺度解耦

`ExecutionOptions` 新增内部的 `maximumDrawingDimension=768`。生成执行计划时使用：

```text
有效鼠标比例 = 用户鼠标比例 × min(1, 768 / 路径最长边)
```

因此 `688×1504` 的高分辨率路径会以约 `0.5106` 的比例转换为鼠标移动，不会因为线稿分辨率提高而让VRChat中的实际绘制范围接近翻倍。路径预览仍根据执行计划中的实际比例反算到逻辑图片坐标，预览与真正执行的命令来源保持一致。

自动化测试另外构造了 `1536×1024` 路径，确认执行比例为 `0.5`、鼠标移动跨度不超过768，并能从执行坐标还原到原路径端点，误差不超过1个逻辑像素。

### 11.3 粗黑区域不再直接生成中轴树

路径构建现在先计算墨迹内部距离场并估计典型局部半径，再区分普通细线和明显粗黑核心：

```text
线稿掩码
→ 普通骨架
→ 墨迹内部距离变换
→ 识别并清理粗黑核心
→ 在原墨迹内受限扩张到完整粗黑区域
→ 删除粗黑区域内部中轴
→ 用粗黑区域边界替代中轴树
→ 与细线骨架合并
```

这使填充眼睛、阴影块和粗黑图案优先表现为轮廓，不再把区域中轴的三叉或星状结构当成真实绘画路径。合成的填充圆、黑色椭圆和“粗线连接细线”测试均只生成1条路径，受保护中心区域的路径点和端点数量均为0。

### 11.4 多尺度稳定分支与交叉点修正

程序同时在半分辨率生成候选骨架，并把能够在半尺度找到对应位置的高分辨率路径标记为稳定支持。毛刺删除只处理同时满足以下条件的分支：

- 位于至少三分支的交叉节点。
- 是连接到普通端点的短终端分支。
- 长度接近局部线宽，且明显短于其他主分支。
- 半尺度稳定支持比例低于40%。
- 方向符合错误角平分线产生的中轴毛刺特征。

长线、独立短组件以及跨尺度稳定的睫毛等细节不会仅因为“短”而被删除。

交叉点还修复了一个高分辨率下会放大的问题：图节点合并后，旧实现直接以节点中心作为每条边的原始端点，可能在节点中心和真实分支入口之间画出跨越白色区域的直线。现在每条边先保留真实骨架入口；共同交点拟合只有在整段仍受原线稿墨迹支持时才会采用，否则回退到原始入口。

### 11.5 受墨迹约束的轻量矢量化

路径使用 `0.35 × 处理尺度` 的RDP误差进行轻量简化。简化结果只有在每一段都位于线稿墨迹支持范围内时才会采用，否则保留原始骨架点。该步骤减少的是同一几何线段上的重复采样点，不合并笔画、不删除线稿组件，也不以压缩笔画数为目标。

最终12张样本的墨迹组件覆盖率均为100%，按1像素容差采样的路径越出线稿比例均为0。这里仍遵守第6节的结论：这些数值只是安全约束，视觉质量由生成图和人工检查共同判断。

### 12.3 结论与边界

本次实施已确认“768分辨率是细节缺失的重要来源”，并完成了分辨率、执行尺寸、粗黑区域和多尺度毛刺处理的架构修改。最终样本路径的画面信息量明显高于原768流程，粗黑测试不再产生中心星状中轴树，路径不会越出线稿形成无依据的连线。

该结果不等于保证VRChat中任何画笔、帧率和视角条件下都与离线路径逐像素一致；那部分仍取决于VRChat输入采样和实际测试。本阶段也没有启用笔画上限或以减少笔画数为目标，后续应先由人工确认本目录中的最终路径图，再单独讨论实际绘制时间和笔画预算。
