# VRC-Draw MVP 设计方案

## 1. 文档说明

本文档整理当前已经确认的产品目标、技术选型和 MVP 范围。现阶段重点不是在 VRChat 中精确复原图片，而是验证一条最短可行链路：将输入图片转换为单色笔画路径，再通过鼠标移动和鼠标左键让 VRChat 画笔近似绘制该图片。

> 2026-07-26更新：绘制大小和运行时自动输入判断已经实施。详细算法、边界和验证见[绘制缩放与自动鼠标适配方案](VRC-Draw-绘制缩放与自动鼠标适配方案.md)。本文后续章节中仅描述“相对移动”的旧段落现在只对应自动判断后的中心锁定后端。

> 2026-07-27更新：规范线稿、阶段二拓扑修复和阶段三直线／贝塞尔拟合均已完成。用户实绘确认效果可用，0.2.0默认启用阶段三，并保留软件目录设置中的阶段二兼容回退开关。实现结果和最新14张样本数据见[线稿与真实绘制路径质量改进方案](VRC-Draw-真实绘制路径矢量拟合方案.md)。

本文档中的“笔画”指一次完整的鼠标左键按下、路径移动和鼠标左键释放过程。

## 2. 产品目标

VRC-Draw 是一个轻量级 Windows 桌面工具。用户导入图片后，程序提取图片中的单色绘制路径，并通过自动判断的相对或桌面绝对鼠标移动与鼠标左键完成近似绘制。VRChat使用中心锁定相对输入，微软画图等普通桌面程序使用精确绝对坐标输入。

MVP 的成功标准是：

- 图片可以被转换为可执行的单色笔画路径。
- 软件可以稳定控制鼠标移动、左键按下和左键释放。
- VRChat 画笔绘制出的结果能够大致辨认出原图。
- 绘制过程中可以随时通过开始/暂停快捷键暂停。
- 软件体积、内存和依赖保持轻量。
- 用户不需要理解复杂图像处理参数。

## 3. 明确不追求的目标

VRChat 中的画笔、视角和鼠标输入本身存在误差，因此 MVP 不追求精确复刻。以下内容不在当前设计范围内：

- 不保证不同用户的绘制结果完全一致。
- 不保证不同距离、视角和鼠标灵敏度下的绘制尺寸一致。
- 不追求像素级还原。
- 不识别或框选 VRChat 画布。
- 不进行四点标定、透视修正或三维坐标换算。
- 不读取 VRChat 的摄像机、画笔或世界数据。
- 不实现多颜色绘制或自动切换颜色。
- 不实现复杂的专业图像参数面板。
- MVP 暂不根据笔画上限改变生成结果。

## 4. 已确认的 MVP 范围

### 4.1 MVP 包含

- C++23 项目。
- 现代、轻量的桌面 UI。
- PNG、JPEG、BMP 图片导入。
- 固定尺寸的图片预处理。
- 单色图像转换。
- 固定算法的轮廓和路径生成。
- 绘制路径预览。
- 可拖动的“笔画上限”预留滑块。
- `0.30×～3.00×`绘制大小滑块。
- 自动判断中心锁定相对移动或桌面绝对坐标移动。
- 鼠标左键按下和释放。
- 可修改的全局开始/暂停热键。
- 自动显示、只读且鼠标穿透的绘制进度悬浮窗。
- 开发阶段允许向当前前台程序发送绘制输入，便于本地调试。
- 异常退出时强制释放鼠标左键。
- 少量本地设置存储。

### 4.2 MVP 暂不包含

- 笔画预算和细节分级算法。
- 根据笔画上限筛选路径。
- 素描排线和阴影密度控制。
- 轮廓模式、素描模式等模式切换。
- 颜色量化、调色板和多图层。
- 画布位置识别和框选。
- 鼠标灵敏度校准。
- 跨设备绘制尺寸一致性。
- 中断后的精确位置恢复。
- 云端存储、账户系统和遥测。

## 5. 用户使用流程

```text
启动 VRC-Draw
    ↓
打开或拖入图片
    ↓
程序自动生成单色绘制路径
    ↓
用户查看路径预览
    ↓
用户切换到 VRChat，并将画笔放到合适位置
    ↓
用户按一次开始/暂停热键
    ↓
程序移动鼠标并控制鼠标左键完成绘制
    ↓
绘制期间自动显示进度悬浮窗；暂停或完成后自动隐藏
```

软件不要求用户在 VRChat 中框选画布。绘制从用户当前准备好的位置开始，最终结果允许存在位置、大小和形状误差。

## 6. 技术栈

| 模块 | 选择 | 说明 |
|---|---|---|
| 主要语言 | C++23 | 核心逻辑、图片处理、UI 和输入控制 |
| 编译器 | MinGW-w64 GCC；兼容 MSVC 2022 | Windows x64 构建，发布预设使用 MinGW-w64 |
| 构建系统 | CMake | 设置 `CMAKE_CXX_STANDARD 23` |
| UI | Dear ImGui | 轻量、可定制、无 Qt 运行库 |
| UI 渲染 | Direct3D 11 | Windows 系统图形 API |
| 悬浮窗 | 独立 Win32 顶层窗口、自绘 GDI | 半透明、置顶、鼠标穿透、无原生控件 |
| 图片解码 | Windows Imaging Component | 读取 PNG、JPEG 和 BMP |
| 鼠标输入 | Windows `SendInput` | 自动判断相对/绝对移动、左键按下和释放 |
| 全局热键 | `RegisterHotKey` | 开始/暂停绘制 |
| 配置 | INI | 少量设置，无需数据库 |
| 并发 | `std::jthread`、`std::stop_token` | 后台处理和可取消绘制任务 |
| 错误处理 | `std::expected` | 返回图片和输入执行错误 |

### 6.1 不采用 Qt

Qt 的 UI 能力完整，但运行库和部署体积不符合当前轻量化目标。前端 UI 不应成为程序体积的主要来源，因此 MVP 不引入 Qt。

### 6.2 不采用 Win32 原生控件

Win32 仍用于创建窗口、接收消息和注册热键，但不使用 `BUTTON`、`TRACKBAR`、`STATIC` 等原生控件。主窗口控件由 Dear ImGui 绘制；悬浮窗使用 GDI 自绘文字和进度条。两者都不采用传统 Win32 控件，避免外观陈旧和主题不统一。

### 6.3 MVP 不引入完整 OpenCV

完整 OpenCV 会明显增加依赖和部署体积。MVP 所需的灰度化、缩放、XDoG 风格暗线提取、形态学处理、骨架细化、图结构追踪和路径简化均由 WIC 与自有 C++ 实现。

如果后续算法复杂度显著增加，再评估只编译 OpenCV 必要模块，而不是直接分发完整 OpenCV。

## 8. UI 设计

### 8.1 设计原则

- 主界面只显示用户完成绘制所必需的内容。
- 不暴露边缘阈值、平滑度、排线角度等算法参数。
- 使用亮色主题、白色内容卡片、统一圆角和蓝色强调色。
- 中文字体使用 21px，并将字形视觉基线向上修正 1px。
- 图片预览区域占据主界面的大部分空间。
- 绘制进度和预计剩余时间在悬浮窗中必须清晰可见。
- 不使用注入式游戏内覆盖层；主窗口和悬浮窗都是独立桌面窗口。

### 8.2 MVP 主窗口示意图

```text
┌────────────────────────────────────────────────────────────────────┐
```

左侧控制栏默认宽度为 320px，可在 280～480px 范围内拖动分隔条调整；说明、状态和错误文字按栏内可用宽度自动换行，内容过高时只进行纵向滚动。右侧预览区随窗口扩展并占据主要空间。状态信息固定在预览上方，只显示绘制进度和预计剩余时间。“执行命令数”和内部图边数仅作为开发测试指标，不出现在普通用户界面。

悬浮窗默认隐藏，开始绘制时自动显示在鼠标所在显示器的右上角；暂停、完成、取消或出错时自动隐藏。它采用黑色半透明背景和白色文字，没有标题、图标、按钮或单独快捷键。窗口始终置顶、不激活且鼠标穿透，因此不会抢占 VRChat 的焦点或点击：

```text
┌──────────────────────────────────┐
│ 绘制进度：38.0%        剩余 01:42│
│ ███████████───────────────────── │
└──────────────────────────────────┘
```

悬浮窗不是 VRChat 注入层，不读取游戏画面、内存或窗口内容，仅显示应用自身的执行计划进度。

### 8.3 快捷键修改

- 开始/暂停默认使用 `F8`，悬浮窗没有快捷键。
- 点击左侧对应快捷键按钮后，直接按新的按键或包含 Ctrl、Alt、Shift、Win 的组合键。
- 按 `Esc` 取消修改。
- 修改时临时注销开始/暂停快捷键，避免原绑定抢占按键消息。
- 新组合注册失败时恢复旧绑定并提示该组合可能已被占用。
- 成功后立即写入软件目录的 `data/settings.ini`。
- 旧版悬浮窗快捷键配置不再读取，并在下次保存设置时移除。

### 8.4 预留滑块行为

滑块在 MVP 中可以拖动，并将数值保存到设置中，但图片处理和路径生成暂时不读取该数值。

```cpp
struct DrawSettings
{
    int futureStrokeLimit = 300;
};
```

建议范围：

- 最小值：20
- 默认值：300
- 最大值：1000
- 步进值：10

MVP保留该滑块，以便后续直接接入笔画预算功能；滑块旁必须始终注明“预留功能，当前不影响结果”，不能让用户误以为它已经改变路径生成。

### 8.5 程序图标

- `assets/vrc-draw.svg` 是图标唯一可编辑原始资源。
- `tools/generate_icon.py` 从该 SVG 分别渲染 16、20、24、32、40、48、64、128 和 256 像素图像。
- 这些图像写入包含 9 个目录项的 `resources/VRC-Draw.ico`，再通过 `.rc` 资源脚本编译进 EXE。
- 同时生成 `resources/icons/VRC-Draw-<尺寸>.ico` 九个单尺寸文件，便于逐个查看；Windows 预览器通常只展示复合 ICO 的一个内部尺寸。
- 普通构建直接使用仓库中已生成的 ICO；只有修改 SVG 的开发者需要 Python 和 Pillow。

## 9. 图片处理方案

### 9.1 固定处理流程

```text
WIC 解码
    ↓
按比例缩放，最长边不超过1536且最多240万像素
    ↓
透明区域合成白底、感知灰度与轻量保边降噪
    ↓
PS式三尺度响应、原暗线脊与RGB单边界融合
    ↓
自动响应色阶、弱桥删除和方向约束有限补线
    ↓
规范线稿响应
    ├─→ 灰度覆盖线稿 ─→ 线稿页面、抗锯齿PNG、亚像素路径SVG
    ↓
二值拓扑线稿
    ↓
Zhang-Suen 骨架细化
    ↓
骨架压缩为端点、交叉点和线段组成的拓扑图
    ↓
粗黑区域轮廓化、多尺度毛刺过滤和受墨迹约束的 RDP
    ↓
无重复边的欧拉迹分解和严格端点连接
    ↓
闭环起点、方向和空笔顺序优化
    ↓
生成带零差异质量门禁的单色笔画列表
```

当前实现把图片最长边限制为1536，同时限制最多240万像素，高度和宽度按原比例缩放。该尺寸是内部常量，不作为用户设置。最终鼠标执行范围独立限制为最长边约768，线稿处理尺寸不会直接放大VRChat中的绘制范围。

当前流程从同一规范响应生成两份用途明确的数据：保留中间覆盖值和原线宽的灰度线稿用于预览与导出，二值拓扑线稿用于路径分析。程序不再对全图执行会粘合近邻线条的闭运算，只在端点方向、距离和弱响应走廊同时支持时有限补线。普通细线在路线分支中骨架化；明显粗黑或填充区域删除内部中轴树，改用区域轮廓。线稿不得由鼠标路径反向栅格化，否则线稿页就会错误地变成路径图。

### 9.2 路径数据

```cpp
struct Point
{
    float x;
    float y;
};

struct Stroke
{
    std::vector<Point> points;
};

struct DrawingPath
{
    int width;
    int height;
    std::vector<Stroke> strokes;
    std::vector<std::vector<std::size_t>> sourceEdgeEnds;
    PathOptimizationStats optimization;
};

struct BinaryImage
{
    int width;
    int height;
    std::vector<std::uint8_t> pixels;
};

struct GrayImage
{
    int width;
    int height;
    std::vector<std::uint8_t> pixels; // 0=白，255=完全黑，中间值为覆盖率
};

struct LineArtDocument
{
    GrayImage coverageLineArt; // 线稿页与PNG/SVG导出的灰度覆盖图
    BinaryImage cleanLineArt;  // 路径拓扑分析使用的同源二值图
    DrawingPath strokes;       // 路线预览和鼠标执行使用的路径
};
```

MVP 只保存单色路径，不保存颜色、压力、笔刷宽度或图层。

### 9.3 路径简化

路径点过密会增加鼠标事件数量，但过度简化会让图形失真。当前只使用 `0.35 × 处理尺度` 的轻量Ramer-Douglas-Peucker简化，而且简化后的每一段都必须受原线稿墨迹支持，否则保留原始骨架点。不再启用会改变轮廓的三点平滑、短路径删除或跨空白合并。

质量路径生成后，无损优化器只连接浮点端点严格相同的图边，使用Hierholzer算法生成最少无重复边迹。每条原始边访问且只访问一次，不允许通过回走重复描线。优化前后的逻辑线段和最终落笔鼠标移动线段必须完全相同，预计时间也不得增加，否则自动回退。路线顺序使用实际空笔命令代价和有限窗口2-opt优化，不改变落笔几何。

这些参数暂时作为内部常量，不显示在 UI 中。

## 10. 鼠标绘制方案

### 10.1 核心原则

VRChat 画笔直接跟随相对鼠标输入，而微软画图等桌面程序依赖实际光标位置。程序不根据进程名称区分目标，而是在开始时用抬笔移动观察光标是否被拉回中心，自动选择输入后端。无需识别VRChat画布或计算摄像机角度。

### 10.2 自动判断和双输入后端

对于同一条笔画中的相邻路径点：

```cpp
const float pathDx = next.x - current.x;
const float pathDy = next.y - current.y;

const int mouseDx = RoundWithRemainder(pathDx * kMouseScale);
const int mouseDy = RoundWithRemainder(pathDy * kMouseScale);
```

中心锁定目标使用相对鼠标移动：

```cpp
INPUT input{};
input.type = INPUT_MOUSE;
input.mi.dx = mouseDx;
input.mi.dy = mouseDy;
input.mi.dwFlags = MOUSEEVENTF_MOVE;

SendInput(1, &input, sizeof(INPUT));
```

桌面光标目标则把累计路径位置加到开始时的鼠标锚点，映射到整个虚拟桌面的 `0～65535` 坐标并使用 `MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK | MOUSEEVENTF_MOVE_NOCOALESCE`。它不会受到Windows指针速度和加速度影响。

执行范围仍以最长边约768为 `1.00×`基准，用户可以通过 `0.30×～3.00×`绘制大小滑块调整。缩放发生在路径点转换阶段，转换后重新执行最大单步插值。

浮点线稿必须先转换为唯一的 `ExecutionPlan`。绘画路线预览和实际 `SendInput` 执行共同消费这份计划，禁止在预览器和执行器中分别计算路径。

### 10.3 单条笔画执行

```text
确保左键处于释放状态
    ↓
移动到当前笔画起点
    ↓
按下鼠标左键
    ↓
按照自动判断的后端依次发送鼠标移动
    ↓
释放鼠标左键
```

移动到下一条笔画起点时保持鼠标左键释放。程序内部维护当前虚拟路径位置，从当前笔画终点计算到下一笔起点的相对位移。

### 10.4 移动插值

如果相邻路径点产生的鼠标增量过大，需要拆分为多个较小的相对移动，以减少线条断裂：

```text
(dx, dy)
    ↓
根据最大单步距离计算分段数
    ↓
均匀拆分成多个小移动
    ↓
以固定节奏发送
```

MVP 使用固定发送频率，最大单步距离只根据路线拐角确定。不得加入用于伪装人工操作的随机抖动或随机延迟。

插值使用保持原线段比例的 DDA 算法，不能分别对 X/Y 使用独立 `clamp`。每个目标点的鼠标增量累加结果必须严格等于目标坐标。

当前内部时序不会让空笔和落笔使用相差悬殊的移动增量：

| 状态 | 最大单步 | 移动间隔 |
|---|---:|---:|
| 落笔直线段 | 6 | 16 ms |
| 落笔急转弯 | 2～5 | 16 ms |
| 笔画间空笔移动 | 6 | 16 ms |

落笔前等待 16 ms，按下后等待 16 ms，抬笔后等待 32 ms。除此之外，任意相邻两次 `LeftDown` 的计划时间至少间隔 600 ms，避免 VRChat 将两个很短且相邻的笔画识别为双击并召唤橡皮。笔画内移动、抬笔等待和空笔移动已经花费的时间都计入 600 ms，只补充不足部分。执行器在每次实际发送 `MOUSEEVENTF_LEFTDOWN` 前还使用 `steady_clock` 再次校验物理间隔，覆盖暂停后恢复未完成笔画等不经过新 `LeftDown` 计划命令的情况。短等待由 Windows 高精度 Waitable Timer 实现。线程不使用忙循环，暂停或停止最迟在当前 16 ms 等待切片结束后生效。

Windows 会按照系统鼠标速度和加速度处理 `MOUSEEVENTF_MOVE` 相对增量，所以该方式只用于鼠标被锁定在中心的目标。桌面光标模式使用绝对坐标并在开始前校验完整路径是否位于虚拟桌面；超出时拒绝开始，不裁剪路径。两种模式共享相同的逻辑最大单步和等待时序。

`ExecutionPlan` 同时包含 `Move`、`LeftDown`、`LeftUp` 和 `Wait` 命令。路线页仍从最终 `ExecutionPlan` 重建，但只显示左键按下期间的移动，也就是用户最终会看到的实线路径；初始定位和笔画之间的空笔移动不显示，不再绘制橙色虚线或起终点装饰。

## 11. 绘制状态与安全控制

### 11.1 状态机

```text
Idle
  ↓ 导入图片
ImageReady
  ↓ 路径生成完成
Ready
  ↓ 按一次开始/暂停快捷键（默认 F8）
Drawing
  ├─ 再按一次该快捷键 ─→ Paused
  ├─ Paused 状态再次按下 ─→ Drawing
  └─ 发生错误 ─→ Error
```

进入 `Drawing` 时显示悬浮窗；离开 `Drawing` 状态后立即隐藏。悬浮窗不接收任何控制输入。

### 11.2 安全要求

- 开发阶段不要求当前前台程序必须是 VRChat；开始时自动判断目标使用中心锁定还是桌面光标。
- 绘制会话绑定开始时的前台进程；前台进程改变时立即释放左键并暂停。
- 开始/暂停采用切换方式：按一次开始，再按一次暂停，默认 `F8`。
- 绘制大小、左侧控制栏宽度和开始/暂停快捷键保存在便携设置中，悬浮窗没有快捷键或按钮。
- 暂停、完成、取消和输入错误时必须自动隐藏悬浮窗。
- 暂停、停止、异常和程序退出时必须发送鼠标左键释放。
- 鼠标左键状态使用 RAII 保护，避免异常后持续按住。
- 绘制线程使用 `std::stop_token`，不得依赖强制终止线程。
- 输入发送失败时立即停止，不进行无限重试。
- 不允许后台无人值守绘制。

## 12. VRChat 合规边界

软件只采用操作系统公开输入接口，但外部鼠标自动化是否被 VRChat 允许，最终取决于发布和使用时的 VRChat 官方规则，不能仅凭“不注入游戏”保证零风险。

技术实现必须遵守以下边界：

- 不注入 VRChat 进程。
- 不读取或修改游戏内存。
- 不修改 VRChat 客户端文件。
- 不绕过或干扰反作弊系统。
- 不伪造游戏网络数据。
- 不实现隐藏、反检测或模拟真人输入的功能。
- 不在后台或无人值守状态运行绘制。
- 绘制必须由用户主动启动，并可立即停止。

公开发布前应重新检查当时最新的 VRChat 服务条款、社区规则和自动化工具政策。在没有明确结论时，不应宣传“绝对不会封号”。

## 13. 存储方案

### 13.1 开发阶段

建议仓库结构：

```text
VRC-Draw/
├─ .github/                # CI、Issue 和 PR 模板
├─ assets/                 # 图标 SVG 原始资源
├─ docs/                   # 设计文档
├─ resources/              # ICO 和 Windows 资源脚本
├─ sample/                 # 质量回归测试图片
├─ src/                    # 核心逻辑、主界面和悬浮窗
├─ tests/                  # 单元测试和模拟画布测试
├─ tools/                  # 开发资源生成脚本
├─ CMakeLists.txt
└─ README.md
```

Dear ImGui 可以使用 Git submodule、CMake FetchContent 固定提交版本，或将明确版本的源文件放入 `third_party`。不提交编译目录、PDB 和临时图片。

### 13.2 用户端

软件采用纯便携模式。程序本体、配置、日志、临时文件以及未来可能增加的项目数据全部放在软件目录内。软件不得主动向软件目录之外写入任何数据，删除整个软件目录即可清除 VRC-Draw 自身创建的全部内容。

推荐以 ZIP 压缩包形式发布，用户解压后直接运行：

```text
VRC-Draw\
├─ VRC-Draw.exe
├─ data\
│  ├─ settings.ini
│  ├─ imgui.ini
│  ├─ logs\
│  │  └─ latest.log
│  └─ temp\
└─ exports\
   ├─ image-lineart.png
   └─ image-lineart.svg
```

存储原则：

- 不写入 `%LocalAppData%`、`%AppData%`、`%ProgramData%` 或用户文档目录。
- 不写入 Windows 注册表。
- 不创建开始菜单项目、系统服务、计划任务、文件关联或卸载信息。
- 不在系统 `%TEMP%` 中创建持久文件；确实需要临时文件时，只能使用软件目录中的 `data\temp`。
- 不把配置路径建立在当前工作目录上，必须通过 `GetModuleFileNameW` 获取 EXE 所在目录，再生成所有数据文件的绝对路径。
- Dear ImGui 的默认 `imgui.ini` 路径必须显式重定向到 `data\imgui.ini`，或关闭其默认 INI 写入并由程序统一保存。
- 如果软件目录不可写，程序应显示错误并停止保存，不得静默回退到 AppData、注册表或其他目录。
- 用户应将软件解压到具有写权限的普通目录，不建议放在 `Program Files` 下。
- 不复制用户原始图片。
- 不创建图片缓存数据库。
- 图片处理结果默认只存在内存中。
- 不上传图片。
- 默认不启用遥测。
- 日志只记录程序状态和错误，不记录图片内容。
- 日志设置固定大小上限，例如 1～2 MB。
- MVP 暂不实现项目文件保存。
- 用户点击“导出线稿”后，同时在 `exports` 中生成 PNG 和 SVG；重名时自动追加编号。

这里的“完全清除”是指 VRC-Draw 主动创建和管理的所有文件。Windows 自身可能产生 Prefetch、系统安全日志、文件访问记录等操作系统级痕迹，这些内容不由 VRC-Draw 创建或控制，软件也不会尝试删除或规避它们。

## 14. 性能和体积目标

以下为目标值，最终以 Release 构建和实际测试为准：

| 项目 | MVP 目标 |
|---|---:|
| EXE 体积 | 3～10 MB |
| 分发形式 | ZIP 便携版，不使用安装程序 |
| 空闲内存 | 15～40 MB |
| 载入普通图片后的内存 | 30～100 MB |
| 1080p 图片预处理 | 1 秒左右完成 |
| 路径预览更新 | 100 ms 以内 |
| 绘制期间 CPU | 目标低于 2% |
| 配置文件 | 小于 20 KB |
| 日志 | 最大 1～2 MB |

绘制线程需要使用定时等待，不得使用忙循环持续占用 CPU。D3D11、WIC 和 Win32 均使用 Windows 自带组件，不随程序重复分发。

2026-07-26阶段二以前的MinGW Release历史基线使用当时的12张样本：笔画数从10,762降到5,024，预计总绘制时间从113.08分钟降到65.42分钟；落笔移动命令保持121,978不变，抬笔移动命令减少15.76%。12组逻辑路径图和执行路径图均与优化前逐字节相同。提速只来自共享端点笔画合并、防双击等待减少和空笔路线优化，不删除或重复任何路径边。当前仓库已经扩展为14张样本，最新阶段二／阶段三质量、耗时和内存结果见[线稿与真实绘制路径质量改进方案](VRC-Draw-真实绘制路径矢量拟合方案.md)。游戏实际可用速度仍以目标程序实绘为准。

## 15. 测试方案

### 15.1 图片处理测试

- PNG、JPEG、BMP 能正确载入。
- 超大图片会先缩放，不造成异常内存占用。
- 透明图片正确合成到固定背景后处理。
- 空白图片不会生成无意义路径。
- 极小轮廓可以按固定规则过滤。
- 三像素粗线在骨架化后只产生一条中心线，不产生两条平行边缘。
- 线稿页面和PNG导出保留灰度中间覆盖与骨架化之前的完整墨迹宽度，与路径页面明确分离。
- 1～3像素间隔的近邻平行线在移除全图闭运算后保持分离。
- SVG使用亚像素闭合 `<path>` 和奇偶填充保留孔洞，不输出逐像素矩形。
- 交叉点允许多条图边经过，不因像素已访问而截断剩余分支。
- `sample`目录中的全部PNG自动纳入质量回归，不使用固定三张样例上限；测试使用统一的防失控时间限制，并逐图检查质量约束。

### 15.2 本地模拟画布测试

在连接 VRChat 之前，先制作一个本地测试窗口：

- 按下鼠标左键时记录轨迹。
- 松开时结束当前笔画。
- 显示实际接收到的鼠标移动路径。
- 对比生成路径和实际执行路径。

该测试用于验证鼠标坐标差、路径间移动、舍入余数和左键状态，不涉及游戏。

### 15.3 VRChat 手动测试

- 简单矩形、圆形和三角形。
- 少量笔画的 Logo 或线稿。
- 不同鼠标移动速度下是否断线。
- 再次按下开始/暂停快捷键后能否立即释放画笔。
- 切出 VRChat 后能否立即停止。
- 悬浮窗自动出现时是否保持 VRChat 的键盘和鼠标焦点。
- 暂停、完成、取消或错误后悬浮窗是否立即消失。

MVP 的效果验收以“大致可辨认”和“输入稳定”为准，不以尺寸或像素误差为验收指标。

## 17. MVP 验收标准

- Release 版本使用 C++23 构建成功。
- 不依赖 Qt、Electron 或完整 OpenCV。
- 普通 PNG、JPEG、BMP 图片可以导入并显示预览。
- 图片能自动转换成单色路径。
- 原图、线稿和绘画路线使用三个互相独立的预览页面。
- 路线预览直接由最终 `ExecutionPlan` 重建，而不是显示执行前的浮点路径。
- 浅斜线、陡斜线和负方向线段在插值后保持方向，全部鼠标增量严格到达目标点。
- 笔画之间包含固定抬笔等待，减少空笔移动被错误绘制的情况。
- 相邻 `LeftDown` 至少间隔 600 ms，短笔画序列不会触发 VRChat 双击橡皮操作。
- 线稿可以同时导出为 PNG 和 SVG，内容与线稿预览使用同一份完整墨迹，而不是鼠标中心线路径。
- UI 使用亮色背景、白色卡片和蓝色强调色。
- 左侧集中显示控制组件，支持拖动调整栏宽且文字自动换行；右侧大预览区上方显示笔画进度和预计剩余时间。
- 普通用户界面不显示内部鼠标命令数。
- 开始/暂停全局快捷键可以重新绑定并持久化。
- 悬浮窗不提供快捷键、标题、图标、按钮或任何交互。
- 悬浮窗仅在绘制期间自动显示笔画进度和剩余时间，离开绘制状态后自动隐藏。
- SVG 是图标唯一原始资源，生成的九尺寸复合 ICO 已编译进 EXE，并保留九个单尺寸 ICO 供检查。
- 本地模拟画布能按照路径完成多笔绘制。
- 任意本地测试画布位于前台时，能够自动判断为桌面绝对坐标并用左键绘制简单图形。
- VRChat等锁中心目标能够自动判断为相对输入。
- 绘制大小可以在 `0.30×～3.00×`调整并保存在便携设置中。
- 再次按下开始/暂停快捷键后，鼠标左键必定释放。
- 开发阶段不要求启动 VRChat，也不限制当前前台程序。
- 笔画上限滑块可以拖动并保存，但明确标注为预留功能。
- UI 不使用 Win32 原生控件，整体保持简洁和现代。
- 绘制结果允许发生位置、尺寸、比例和细节误差。
- 程序以 ZIP 便携版分发，不使用安装程序。
- 程序主动创建的所有配置、日志和临时文件均位于软件目录内。
- 使用文件系统监控验证程序不会向 AppData、注册表及其他软件目录外的位置写入应用数据。
- 删除整个软件目录后，不再残留任何由 VRC-Draw 主动创建和管理的文件。
